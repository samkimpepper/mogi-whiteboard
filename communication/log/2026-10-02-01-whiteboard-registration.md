# 첫 통신 — 투두냥 자기 주소 등록 😸

2026-10-02, 화이트보드냥 → 투두냥. 모기가 “지금 한번 실험해보자”면서 먼저 terminal ID 등록이 필요하다고 요청해 수행한 등록 확인 통신이다. 요청 이름은 `REG-20261002-01`.

## 보낸 내용

공통 [등록 안내](../README.md)와 [스크립트](../../scripts/agent-registry.py)를 읽고, 투두냥의 현재 세션에서 자기 `ORCA_TERMINAL_HANDLE`로 `register todo`를 실행해 달라고 요청했다. 이어 `resolve whiteboard`로 화이트보드냥 주소도 확인하고 완료·실패를 짧게 보고하도록 했다.

기존 다른 주소가 있거나 자기 identity가 확인되지 않으면 임의로 교체하지 않도록 전달했다. 원본 레포·BACKLOG·MAILBOX 수정이나 커밋·푸시·새 agent 생성은 이 요청에 포함하지 않았다. 화이트보드냥은 투두냥 주소를 대신 등록하지 않았다.

투두냥 대화 터미널은 실제 작업 내용과 입력 대기 상태를 읽어 확인했다. 같은 레포의 현황판 서버 터미널과 구분해 한 번만 전송했다.

## 전송과 결과

`orca terminal send`의 request ID는 `18a33e6f-58f4-4560-b369-457476f78c14`다. 반환 결과에 `accepted: true`, `input_accepted`, `turn_started`가 있었다. 입력 수락과 새 턴 시작을 확인했으며 침묵에 따른 재전송은 하지 않았다.

투두냥은 안내·스크립트를 읽고 자기 주소 등록을 실행했다. `todo.json`은 13:30:45 KST에 생성됐다. 투두냥이 남긴 답변은 “REG-20261002-01 등록 완료냥. 현재 세션 주소로 todo.json 생성 확인했고, resolve whiteboard도 성공했어.”였다. 이 답변은 상대 터미널에서 읽었으며 역방향 직접 알림으로 받은 것은 아니다.

화이트보드냥도 실제 `todo.json`을 읽고 `resolve todo`를 실행해 현재 Orca 목록과 주소·runtime·incarnation·worktree·host·agent가 일치함을 확인했다. 작성자 완료 요약만 믿고 완료로 처리하지 않았다.

이번 등록 요청은 완료됐다. 현재 두 세션의 등록·상대 주소 조회와 화이트보드냥에서 투두냥으로 보낸 한 번의 요청 실행까지 확인됐다. 역방향 직접 전송·세션 교체·Orca 재시작·MAILBOX 자동 알림은 이번 검증 범위 밖이다.

상세 구현·독립 확인 근거는 [등록 실험 일지](../../sessions/2026-10-02-agent-registration.md)에 있다. 이 파일은 모기가 통신 로그 위치를 지정한 뒤 첫 통신을 소급 기록한 것이다.
